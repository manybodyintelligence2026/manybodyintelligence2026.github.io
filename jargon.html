Common jargon

Plain-English cheatsheet for the AI, Git, terminal, Python, TeX, visualisation, and hackathon terms that come up on Monday 30 November. Ordinary physics jargon is left out.

    1 · Claude & AI

    • Claude (browser) vs. Claude desktop app vs. Claude Code

      The browser version of Claude can only chat. Claude Code (inside the Claude desktop app, the VS Code extension, or a terminal) can read files on your laptop, edit code, run Python/git commands, and open images — always asking your permission first. The free Claude plan does not include Claude Code.

    • Chat mode vs. Code mode (</>)

      The Claude app opens in two modes: the speech bubble is ordinary Chat, and </> is Claude Code. You're in Code mode when Claude shows or asks for a folder on your laptop.

    • Session, prompt, context window, /compact & /clear

      A prompt is one message you send; a session is one conversation thread. Everything in a session sits in Claude's working memory (the context window). Long sessions get slower or lose track of earlier details: type /compact to summarise and free space, or /clear (or start a fresh session) when moving to a new subtask.

    • Usage / rate limits

      Claude plans cap how many heavy messages you can send in a rolling few-hour window. If you hit a limit during the day, let an organiser know — we can switch you to a lighter model, share a teammate's session, or use a fallback.

    • Models: Opus, Sonnet, Haiku

      Three sizes of Claude. Opus is the strongest (best for tricky derivations, planning, or hard debugging, but uses more of your usage limit); Sonnet is the fast everyday workhorse; Haiku is the lightest and quickest for simple tasks.

    • Skill, SKILL.md & slash command (/log-entry, /figure-style, …)

      A skill is a folder containing a plain-text instruction file (SKILL.md) plus optional templates. It teaches Claude a repeatable workflow (like styling journal plots or logging a task). You trigger a skill by typing its slash command (e.g. /scope-to-one-day) or naming it in a prompt.

    • Personal skills (~/.claude/skills/) vs. repo skills (.claude/skills/)

      Your team repo's .claude/skills/ holds the shared bookkeeping skills (/log-entry, /log-check, /stage) — never edit that folder. Optional skills you download from Resources go in your personal ~/.claude/skills/ folder. Always start a new Claude Code session after installing a skill so Claude loads it.

    • CLAUDE.md & CLAUDE.local.md

      Standing instructions Claude automatically reads at the start of every session in a folder. Your team repo's CLAUDE.md holds the shared hackathon rules (don't edit it). Put personal preferences (coding style, favourite tools) in CLAUDE.local.md, which stays private and is never pushed to GitHub.

    • Permission prompt & “Trust this folder”

      Claude Code asks before editing files or running shell commands. Read what it wants to do; if unsure, say no and ask why. Accepting “Trust this folder” when opening your team repo is required so the hackathon's logging hooks run.

    • Artifact (“Don't make an artifact”)

      In Claude's chat UI, an artifact is a preview card shown only inside the app rather than saved as a real file in your folder. Saying “don't make an artifact” tells Claude to write an actual file in your team repo instead.

    • Subagent & MCP (Model Context Protocol)

      A subagent is a temporary helper session Claude spawns to search files or run an independent task in the background. MCP is a standard plug-in protocol that lets Claude talk directly to external apps (such as BlenderMCP for driving Blender live).

    • Hooks, transcripts & working unrecorded

      Hooks are small scripts triggered automatically by Claude Code (here, showing your status block at session start and uploading your session transcript when it ends if you opted in). Need an unrecorded session? Run MBI_NO_RECORD=1 claude or sh scripts/mbi skip <session>.

    • Parallel sessions & “second AI” check

      You can open more than one Claude Code session on different subtasks at once. Asking the same session to check its own answer is not independent (it anchors on its previous reasoning); a second-AI check means opening a fresh session with no shared history and asking it to attack or re-derive the result.

    • Hallucinated references

      AI models sometimes invent plausible-sounding paper titles, authors, or page numbers from memory. That's why our rules insist on a real DOI or arXiv ID (and checking the paper yourself) before citing anything.

    2 · Terminal, files & OS

    • Terminal / shell (PowerShell, bash, Git Bash, WSL)

      A text window where you type commands for your computer. macOS and Linux use bash/zsh; Windows has PowerShell by default, plus Git Bash (installed with Git) or WSL (Windows Subsystem for Linux, a full Linux shell inside Windows) for running sh scripts/... commands.

    • Command & flag (--pid, --transcripts)

      A command is the program you run (e.g. sh scripts/setup); a flag starts with - or -- and passes an option to it (e.g. --pid P14 --transcripts no).

    • PATH

      The list of folders your computer searches when you type a program name like python or git. If a program is installed but not on PATH, the terminal reports “command not found”.

    • File path, home folder (~), dot-folders & current folder

      A path is a file's address (e.g. code/fig_gap.py). ~ is shorthand for your personal home folder (C:\Users\you on Windows, /Users/you on Mac). Folders starting with a dot (like .claude/ or .git/) are hidden by default. Always open Claude Code in the top folder of your team repo (MBI-2026/teamN), not a subfolder.

    • Scripts (.sh, .ps1)

      Plain-text files containing terminal commands to run in sequence: .sh is a bash/shell script (macOS, Linux, Git Bash), and .ps1 is a Windows PowerShell script.

    • Markdown (.md) & JSON (.json)

      Markdown is plain text with light formatting (# headings, **bold**, tables) — used for README.md, plan.md, logs, and note/note.md. JSON is structured key-value data (used for event.json and saved calculation outputs).

    • Admin rights, Software Centre & package manager

      Admin rights let you install programs system-wide. On managed Uppsala University Windows laptops without admin rights, install approved software (VS Code, Git, Python) from the Software Centre. On Linux/Mac, a package manager (apt, brew) installs tools from the terminal.

    • localhost / python -m http.server

      localhost (or 127.0.0.1) is your own laptop pretending to be a web server. Running python -m http.server 8000 lets you preview HTML/3D demos at http://127.0.0.1:8000 when double-clicking a file:// page is blocked by browser security rules.

    3 · Git & GitHub

    • git vs. GitHub, repository (repo) & organisation

      git is the version-control program on your laptop that tracks changes to a folder. GitHub is the website hosting the shared copy of that folder (a repository, or repo). All team repos (team1–team5) live privately inside the manybodyintelligence2026 GitHub organisation.

    • Local vs. remote: clone → edit → commit → pull → push

      Clone downloads the repo once to your laptop. Saving a file only changes your laptop (local). Commit records a labelled snapshot locally; pull fetches teammates' latest commits from GitHub (remote); push uploads yours so your team can see them.

    • git pull --rebase

      Downloads your teammates' new commits and neatly replays your local commits on top of them, avoiding messy merge commits. Our setup script configures this automatically; always pull before you push.

    • Branch (main vs. mbi-transcripts/P##)

      A parallel version of a repo's history. Everyone on your team works and pushes on the default main branch; automated transcript uploads go quietly to separate mbi-transcripts/P## branches (leave those alone).

    • Merge conflict

      Happens when two teammates edit the exact same lines of a file (e.g. README.md) before pulling. Git pauses and marks both versions in the file; you (or Claude) pick the combined text, commit, and push. Keeping work-in-progress in your own <name>/ folder prevents most conflicts.

    • Force-push (never do this!)

      git push --force overwrites GitHub's history with yours and can erase teammates' commits. Our commit history is part of the hackathon record — never force-push or allow Claude to do so.

    • Personal access token (PAT) & git credential manager

      A fine-grained token is a temporary, limited-scope password for programs so Claude/git can push to your team repo without your main GitHub password. The git credential manager stores it securely once so you don't re-enter it. Never paste a token inside your repo or Discord.

    • README.md, .gitignore, GitHub Pages & GitHub Actions

      README.md is the front page of your repo. .gitignore lists files git should never upload (like temporary cache files). GitHub Pages turns a repo into a website (how this event site is hosted). GitHub Actions runs automated checks on every push — your team repo runs bookkeeping.yml, so a red × next to a commit just means a bookkeeping item isn't filled in yet (not that your code broke).

    4 · Python & editors

    • Python 3.8+, package / library & pip

      Python is the scripting language used for both the bookkeeping scripts and most plots/calculations. A package (or library) is reusable code like numpy, matplotlib, or cmcrameri; pip is Python's installer (e.g. pip install cmcrameri).

    • Virtual environment (venv / conda)

      A self-contained folder holding a specific Python version and set of packages so installing something for the hackathon doesn't break other research code on your laptop. Never commit a venv/ folder to git.

    • Matplotlib & .mplstyle files

      Matplotlib is Python's standard plotting library. An .mplstyle file (like our bundled mbi.mplstyle) sets fonts, tick widths, and colour defaults in one place so every figure made by your team looks consistent.

    • VS Code, extension & Restricted Mode

      VS Code is a free code editor where you can edit files and run the official Anthropic Claude Code extension (add-on). When opening a new folder, VS Code may start in Restricted Mode for safety — click “Yes, I trust the authors” or Claude Code won't run.

    5 · Figures, TeX & visualisation

    • Vector (PDF, SVG) vs. raster (PNG, WebP) & DPI

      Vector graphics store mathematical paths and text — they stay razor-sharp at any zoom (use PDF for papers, SVG for editable schematics). Raster images store a pixel grid (PNG for crisp stills, WebP for compact animations). DPI (dots per inch) sets raster sharpness: use ≥ 300 DPI for print.

    • Colour maps: perceptually uniform, Crameri, Paul Tol, SciencePlots & why not jet

      Rainbow maps like jet create fake sharp edges where the data is smooth and break for colour-blind readers. Perceptually uniform maps (like Crameri's batlow, vik, cork, bam) keep brightness honest: use sequential maps for 0→max quantities, diverging maps centred at 0 for signed data (±), and cyclic maps for phases/angles. Paul Tol offers clean discrete line palettes; SciencePlots provides journal Matplotlib presets.

    • LaTeX, TeX distribution (TeX Live, MiKTeX, MacTeX) & Overleaf

      LaTeX is the typesetting language for physics papers. To compile .tex files into PDF on your laptop, you need a TeX distribution — the bundle of LaTeX engine + fonts + packages (TeX Live on Linux/Windows, MiKTeX on Windows, MacTeX on macOS). Overleaf compiles LaTeX in the browser so you don't need a local install.

    • Computer Modern & Matplotlib mathtext

      Computer Modern is LaTeX's classic math font. Matplotlib's built-in mathtext engine renders Computer Modern equations ($E - E_F$) directly inside Python with no TeX distribution installed — our mbi.mplstyle enables this automatically.

    • TikZ

      A LaTeX package for drawing vector schematics and diagrams purely in code, matching your paper's exact fonts and math symbols.

    • Blender, Cycles vs. EEVEE, ray tracing & headless rendering

      Blender is a free, open-source 3D studio controllable from Python. EEVEE is its fast real-time renderer (good for previews); Cycles uses physically based ray tracing (simulating real light bounces, glass refraction, and soft shadows). Headless rendering (blender -b -P scene.py) runs Blender invisibly from the terminal — no clicking menus needed.

    • Manim

      An open-source Python animation library (created for 3Blue1Brown) for scripted mathematical equations, transforms, and explainer videos.

    • VESTA, OVITO & MatterViz

      Domain-specific 3D visualisers: VESTA renders crystal structures and charge densities; OVITO visualises large atomic/molecular dynamics trajectories; MatterViz is a web/interactive toolkit for crystals, 3D Brillouin zones, and Fermi surfaces.

    • Offline HTML animation, Canvas2D, WebGL & Three.js

      A single self-contained .html file that opens in any browser with no internet and runs smoothly at 60 fps — tiny (~10 kB vs. 50 MB video) and interactive during Q&A. Canvas2D draws fast 2D plots/lattices; WebGL uses your GPU for 3D; Three.js is the standard JavaScript 3D library built on WebGL.

    • Shaders (smoothstep.io), fps, URL parameter (?t=2.5) & ffmpeg

      Shaders are tiny GPU programs for smooth real-time wave/field animations (e.g. via smoothstep.io). fps is frames per second (60 fps = silky smooth). Adding a URL query parameter like anim.html?t=2.5 freezes an HTML animation at 2.5 s so Claude can screenshot and inspect it. ffmpeg is a command-line tool that converts frames into .mp4 or .gif if you need a video file.

    6 · Publishing & event rules

    • Event paper vs. project paper

      The event paper is a short paper the organisers write about how the hackathon went (opt-in co-authorship for all participants; never gives away publishable team details). A project paper is any follow-up physics paper your team decides to write from its own results.

    • CRediT roles

      The standard Contributor Roles Taxonomy (Conceptualization, Software, Validation, Writing, etc.) used in CONTRIBUTIONS.md to record who did what cleanly and fairly.

    • Zenodo & CC BY 4.0

      Zenodo is CERN's open research archive that assigns a permanent DOI to datasets, code, and notes. CC BY 4.0 is an open Creative Commons license letting anyone reuse figures or materials as long as they credit the authors.

    • APS / PRB column widths & lightning talk

      Standard Physical Review figure widths: 86 mm (3.375 in) for a single-column figure, 178 mm (7.0 in) for double-column — drawing at the exact final width keeps fonts readable without shrinking. A lightning talk is your team's tight 5-minute summary talk at 15:45.

    7 · Hackathon-specific names & commands

    • Discord channels (#welcome, #team-selection, #technical-help)

      Our event chat server: introduce yourself in #welcome, pick your team in #team-selection to unlock your private team channel, and post screenshots in #technical-help if stuck for more than 10 minutes.

    • Participant ID (P##) & Team ID (T##)

      Short codes (like P14 and T01) used by the bookkeeping tools to name your log file (log/P14.md), log entries (T01-P14-E01), and transcript branches. Real names are fine everywhere in prose.

    • our-idea/, question history (Q0, Q1, Q2) & Confidence (1–5)

      our-idea/ holds each teammate's bio and 2–3 papers. Q0 is your starting question in README.md; if your team sharpens or narrows it during the day, record Q1, Q2 with the time and reason, plus your team's honest Confidence (1–5) rating.

    • plan.md vs. plan-ai.md, tracks & fallbacks

      Created by /scope-to-one-day in Phase 1: plan.md is a one-screen summary for your team; plan-ai.md has the full arithmetic, references, and per-person tracks (so each teammate can start a session with “Read plan-ai.md, I'm on track B”) plus pre-agreed fallbacks if a calculation stalls.

    • Key team repo files (checks/, note/, talk/, review/, photos/)

      checks/checks.md records independent checks (using method names from log/CODEBOOK.md); note/note.md is the 2-page note; talk/ holds slides; review/ holds referee reports; photos/ holds phone snaps of whiteboards/paper derivations; CONTRIBUTIONS.md records CRediT roles.

    • Bookkeeping commands (/log-entry, /log-check, /stage, sh scripts/mbi)

      Type /log-entry after each task (~2 min; use /log-entry no-ai for 15+ min paper/whiteboard work or /log-entry chat for browser-AI work). Use /stage when your team moves to the next phase, /log-check before Write ends to catch unlogged sessions, and sh scripts/mbi doctor / status to check setup or what's still missing.

    • Downloadable phase skills (Scope & Figures)

      Phase 1: /scope-to-one-day (one-day research plan). Phase 4: /figure-style (journal plots), /schematic (editable vector diagrams), /render-and-look (Claude opens its PNG to fix layout), /html-animation & /html-fractal (live offline HTML figures), and /blender-scene (scripted 3D renders).

    • The six phases & Fika

      Scope (09:15) → First attempt & First result (10:15) → Check (13:00) → Make figures (14:00) → Write (15:00) → Talks & Peer review (15:45). Fika (10:00 and 15:00) is the essential Swedish coffee-and-pastry break — plus pizza at 12:15.

    8 · Common errors & quick fixes

    • fatal: detected dubious ownership in repository

      Common on Windows when a repo sits on a second drive (e.g. D:) or shared partition. Run the exact git config --global --add safe.directory ... line printed in the error message (or ask Claude to run it).

    • Authentication failed or Permission denied (publickey)

      Your GitHub token is wrong/expired, or git tried SSH instead of HTTPS. Re-check that you cloned with the https://github.com/... URL and saved a valid fine-grained token with Contents: Read and write.

    • ! [rejected] main -> main (fetch first)

      Totally normal — a teammate pushed while you were working. Run git pull --rebase first, then git push again. Never force-push.

    • command not found / is not recognized

      The program isn't installed yet, isn't on your PATH, or you need to close and reopen your terminal / VS Code after installing it. Ask Claude to check which path it's installed at.

    • Installed a skill, but /skill-name doesn't show up

      Claude Code only scans skills when a session starts. Check that ~/.claude/skills/<skill-name>/SKILL.md exists (not nested inside an extra folder), then start a new Claude Code session.

    • Red × next to your commit on GitHub

      That's the automated bookkeeping checker (bookkeeping.yml), not a code failure. Run sh scripts/mbi status in your repo to see which checklist item is still open.

    • Local HTML / 3D animation opens as a blank page

      Browsers block some scripts when opened directly via file://. Start a local server in that folder (python -m http.server 8000) and open http://127.0.0.1:8000/ instead.
